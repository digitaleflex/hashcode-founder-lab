# Modèle de fonctionnement

## Vision

HashCode Founder Lab transforme des besoins réels en opportunités d'apprentissage.

## Le système

`Besoin réel HashCode → Parcours → Formation → Pratique → Livrable → Feedback → Compétence`

## Les responsabilités

### Apprenant
Apprendre, pratiquer, produire et améliorer.

### Formateur / Mentor
Guider, observer, challenger et donner du feedback.

### Knowledge / Documentation
Structurer et maintenir les connaissances utiles.

### QA
Observer méthodiquement, tester et documenter les problèmes.

### Notion
Piloter l'activité et le suivi.

### GitHub
Versionner et maintenir les contenus professionnels.

## Cycle d'amélioration

Après utilisation d'un contenu :

1. Observer l'expérience.
2. Identifier les difficultés.
3. Collecter le feedback.
4. Corriger le contenu.
5. Versionner l'amélioration.
6. Réutiliser.

## Règle de décision

Une amélioration doit être priorisée lorsqu'elle améliore directement :

- l'apprentissage ;
- la pratique ;
- la qualité des livrables ;
- la capacité du formateur à accompagner ;
- la réutilisabilité du parcours.
